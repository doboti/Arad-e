Projekt Specifikáció: „Hol a víz?” – Valós idejű hazai víz- és aszályfigyelő platform1. A projekt víziója és céljaEgy egyoldalas, letisztult, "görgethető" műszerfal (dashboard) létrehozása, amely a laikusok számára is azonnal érthetővé teszi Magyarország felszíni vízkészleteinek és aszályhelyzetének aktuális állapotát. A cél a száraz, szétszórt állami adatbázisok (vízállások, vízhozamok, talajnedvesség) vizuális történetmeséléssé (data storytelling) alakítása.2. Funkcionális modulok (Mit lát a felhasználó?)A felületet logikai blokkokra érdemes osztani, hasonlóan a Hol a delej? felépítéséhez.A. A Fő Képernyő (Helyzetkép)Kritikus mutatók (Hero Numbers):Balaton átlagos vízállása (cm) + tendencia (nő/csökken).Duna vízállása Budapestnél és Paksnál (az atomerőmű hűtése miatt).Tisza vízállása Szolnoknál.Országos aszályindex / talajnedvesség átlag.Interaktív Térkép: Egy Magyarország-térkép a főbb folyókkal és tavakkal. A mérőállomások színkóddal jelennek meg (kék = áradás, zöld = normál, sárga = alacsony, piros = kritikus aszály/kiszáradás).B. "Nagy Tavaink" ModulKiket figyelünk: Balaton (Siófok), Velencei-tó (Agárd), Tisza-tó.Adatok: Aktuális vízállás, vízhőmérséklet.Kontextus (Ez a legfontosabb!): Ne csak egy számot mutass! Legyen egy grafikon, ami mutatja az aktuális vízszintet a történelmi minimum, a szabályozási maximum és az elmúlt 5 év átlaga viszonylatában.C. Folyók és Vízgyűjtők Modul (Árad vagy apad?)Adatok: Vízállás (cm) és vízhozam ($m^3/s$).Csapadék a vízgyűjtőn: Hasonlóan a Hol a delej? megoldásához, itt össze kell kötni a Duna és a Tisza külföldi vízgyűjtő területein (Alpok, Kárpátok) várható csapadékot a hazai vízállás-előrejelzéssel. (Pl. "Az Inn vízgyűjtőjén eső várható, ez 4-6 nap múlva ér el Paksra.")D. Aszály és Talajnedvesség ModulSzántóföldek állapota: Felső 20 cm és 20-50 cm mélységű talajnedvesség (%). Ez vizuálisan mutatja meg, hol fenyegeti a termést a kiszáradás.3. Adatforrások (Data Ingestion)Mivel nincs egyetlen, tökéletes, publikus API, az adatokat több helyről, különböző módszerekkel kell összegyűjteni.AdattípusForrásKinyerési módszerVízállás, vízhozam, vízhőmérséklet (Folyók, tavak)OVF (hydroinfo.hu / vizugy.hu)A weblap HTML-jének kaparása (Web Scraping). Nincs publikus JSON API, így a táblázatokat kell parse-olni.Időjárás előrejelzés (Vízgyűjtők)Open-Meteo APIIngyenes REST API (JSON).Talajnedvesség / AszályHungaroMet (met.hu) vagy Copernicus EMSWeb Scraping (met.hu) vagy a Copernicus műholdas nyílt API-ja.Történelmi extrémumok (LNV, LKV)Vízügyi nyilvántartásokEgyszeri betöltés (statikus adatbázis), ehhez viszonyítjuk a friss adatokat (LNV = Legnagyobb Vízállás, LKV = Legkisebb Vízállás).4. Javasolt Technológiai Stack (Fejlesztőknek)A projektet érdemes modern, adat-fókuszú architektúrával felépíteni.A. Adatgyűjtés és Feldolgozás (ETL Pipeline)Nyelv: Python 3.10+Könyvtárak: BeautifulSoup4 vagy Scrapy (a Vízügy oldalainak kaparásához), Requests (API hívásokhoz), Pandas (az adatok tisztításához és transzformálásához).Ütemezés: Egy egyszerű cron job, vagy GitHub Actions (óránkénti/napi futtatással), profibb esetben Apache Airflow.B. Adatbázis (Storage)Mivel idősoros (time-series) adatokról beszélünk, relációs adatbázisra van szükség, ami jól bírja az időbélyegeket.Kezdéshez (MVP): SQLite (lokális, egyszerű) vagy ingyenes PostgreSQL (pl. Supabase, Neon.tech).Séma (egyszerűsítve):Stations: ID, Név, Folyó/Tó neve, Koordináták (Lat/Lon), LNV, LKV.Measurements: ID, Station_ID, Timestamp, Vízállás (cm), Vízhozam, Vízhőfok.C. Backend (API réteg)Ennek a rétegnek a feladata, hogy az adatbázisból kiszolgálja a frontendet.Keretrendszer: FastAPI (Python) – villámgyors, automatikus dokumentációt generál, és tökéletes a data science projektekhez.D. Frontend (Dashboard)Két út áll előtted a csapat kapacitásától függően:A "Data Science" gyors út (MVP): Streamlit (Python). Fejlesztői szempontból a leggyorsabb. Csak Pythont kell tudni hozzá, beépített grafikonjai és elrendezései vannak. Pár nap alatt működő prototípusod lehet.A "Hol a delej?" szintű profi út: Next.js (React) + Tailwind CSS a kinézethez, és Recharts vagy Chart.js a grafikonokhoz. Ez egyedi dizájnt, villámgyors betöltést és tökéletes mobil-optimalizációt tesz lehetővé.5. Fejlesztési Mérföldkövek (Roadmap)Mérföldkő: Proof of Concept (PoC) AdatgyűjtésCél: Írni egy Python szkriptet, ami sikeresen letölti és kiírja a konzolra a Balaton, a Duna (Bp) és a Tisza (Szolnok) mai vízállását a vizugy.hu-ról.Mérföldkő: Adatbázis és AutomatizálásCél: A szkript fellövése a felhőbe (pl. egy olcsó VPS-re vagy GitHub Actions-be), hogy óránként mentse az adatokat egy PostgreSQL adatbázisba.Mérföldkő: Alap Dashboard (MVP)Cél: Egy Streamlit alkalmazás összerakása, ami kiolvassa az adatbázist, és megrajzolja az elmúlt 7 nap vízállás-grafikonjait az alapvető mérőállomásokra.Mérföldkő: Kontextus és DizájnCél: A történelmi minimumok/maximumok felvitele a grafikonokra, aszály térkép integrálása, UI/UX finomítása (React frontend készítése).6. Kihívások és kockázatok (Mire kell figyelni?)A Forrásoldal (Vízügy) változásai: A web scraping legfőbb ellensége, ha a forrásoldal dizájnt vált. Ha a Vízügy átalakítja a táblázatait HTML szinten, a gyűjtő szkript el fog törni, és javítani kell. Javasolt riasztást (pl. e-mail, Discord webhook) beépíteni, ha a szkript nem talál adatot.Hiányzó adatok (NaN): A szenzorok néha meghibásodnak, a Vízügy rendszere nem küld adatot. A frontendnek és az adatbázisnak elegánsan kell kezelnie az "üres" (NULL) mezőket, hogy a grafikon ne szakadjon meg csúnyán.Skálázódás: Bár a víz adatok nem változnak másodpercenként (elég óránként lekérdezni), ha az oldal hirtelen népszerű lesz (mint aszály idején), a frontendnek statikusan generált (SSG) vagy gyorsítótárazott (cached) oldalakat kell mutatnia, hogy ne terhelje agyon a backendet.
